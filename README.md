# Порівняння *жадібного алгоритму* та *динамічного програмування* для видачі решти

## Опис завдання
Мета роботи — порівняти ефективність двох підходів до вирішення задачі розміну монет:
1. **Жадібний алгоритм** (`find_coins_greedy`): Завжди вибирає найбільш доступний номінал.
2. **Динамічне програмування** (`find_min_coins`): Знаходить гарантовано мінімальну кількість монет, перебираючи всі можливі комбінації.

## Аналіз часової складності (Big O)

### Жадібний алгоритм
- **Складність:** $O(N)$, де $N$ — кількість номіналів монет.
- **Пояснення:** Алгоритм просто проходить по списку номіналів один раз. Оскільки кількість номіналів фіксована (6 штук), для комп'ютера це миттєва операція $O(1)$ відносно суми.
- **Ефективність:** Дуже висока. Час виконання майже не залежить від розміру суми (тільки кількість арифметичних операцій ділення зростає незначно).

### Динамічне програмування
- **Складність:** $O(A \times N)$, де $A$ — сума решти, $N$ — кількість номіналів монет.
- **Пояснення:** Алгоритм будує масив розміром `amount + 1`. Для кожної комірки цього масиву він перевіряє всі можливі номінали монет.
- **Ефективність:** Низька при великих сумах. Якщо сума збільшується в 1000 разів, час виконання також зростає приблизно в 1000 разів. Також зростають витрати пам'яті $O(A)$ для зберігання таблиці результатів.

## Результати експериментів
При тестуванні на малих сумах (наприклад, 113) обидва алгоритми працюють майже миттєво. Проте різниця стає очевидною на великих числах.

**Приклад (сума 10,000):**
- **Жадібний алгоритм:** ~0.000050 сек
- **Динамічне програмування:** ~0.478491 сек (у тисячі разів повільніше)

*Примітка: При збільшенні суми до 100,000 або 1,000,000 метод динамічного програмування може викликати значні затримки або переповнення пам'яті, тоді як жадібний алгоритм спрацює миттєво.*

## Висновок
Для даного конкретного набору монет `[50, 25, 10, 5, 2, 1]` жадібний алгоритм є оптимальним вибором, оскільки:
1. Він працює екстремально швидко.
2. Для цієї канонічної системи монет він завжди дає оптимальний результат (мінімальну кількість монет), що робить використання важкого динамічного програмування недоцільним.

Метод динамічного програмування варто використовувати лише у випадках, коли набір монет не є канонічним (наприклад, `[9, 6, 1]`), і жадібний підхід не гарантує оптимального рішення.
